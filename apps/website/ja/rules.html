ルール — BeanPoolの仕組み

BeanPoolは誰もがゼロから始めるコミュニティの相互交換システムです。他の人を助けることで豆を獲得し、助けてもらったときに豆を使います。お金のやり取りはなく、仲介企業も存在しません — あるのは以下のシンプルなルールだけです。

要約：取引を通じて信用枠を獲得し、1〜2件の提供を公開してそれを活用し、豆を循環させましょう。 目指すのはゼロ（均衡）です — 受け取った分だけ誰かを助けましょう。

1.豆と残高

豆はあなたが与えた価値と受け取った価値（おおむね時間）を測る指標です。目指すのはゼロです — これは受け取った分とほぼ同じだけ与えたことを意味します。

  • プラスの残高 — 受け取った以上に助けを提供した状態です。コミュニティから感謝（債権）を受けています。
  • マイナスの残高 — コミュニティから信用（クレジット）が与えられた状態です。助けを提供することで返済していきます。
  • 多くのコミュニティでは、マイナスの最大限界値（下限）は−2000豆です。実名でメンバーを確認するコミュニティでは独自に上限（最大−5000まで）を設定し、確認済みメンバーに初期信用枠を付与できます。

2.スタートにあたって

招待によって参加します。初日から閲覧や豆の受け取りが可能です。豆を保有すると（獲得するかギフトを受け取ることで）、それを使うことができます。信用（マイナス残高）を使って支払うには、少なくとも1件の提供を投稿する必要があります（§4および§5を参照）。新規メンバーは信用枠なしでスタートします — 最初の取引が完了して信用枠が有効になるまで（あるいは推薦者や管理者が初期枠を付与するまで — §3および§9を参照）、実際に手持ちの豆のみを使うことができます。

3.取引によって獲得する信用枠

信用枠を利用すると、誰かを助けて豆を稼ぐ前であっても、少し残高をマイナスにして支払うことができます。これは与えられるものではなく、実績で築くものです：

  • 信頼はマーケットプレイスで完了した取引から生まれます — ギフトからは生まれません。最初はゆっくり増えます：100豆の取引で約37豆の信用枠を獲得します。管理者や指定された推薦者が初期信用枠を付与することもでき、管理者の付与はバッジとして表示されます。
  • 多くの異なる相手と取引する方が、特定の1人と何度も取引するよりもはるかに早く信頼を築くことができます。
  • 信頼度によって信用限度額が決まります — 多くのコミュニティでは0から最大−2000まで下限を広げることができます（§1参照）。
  • 下限枠は最初の実際の取引の後に開き、その後の取引ごとに拡大します（あるいはコミュニティの推薦者からスターター枠を受け取ることもできます — §9参照）。推薦は必須ではありません。
信頼レベル — 新規 → 住民 → 世話人 → 長老 — は実績を認めるバッジです。獲得したバッジ自体が何かを制限したり解除したりするわけではありません。より深い信用枠は実際の取引によって得られます。管理者が誰かにバッジを付与することもでき、そのバッジの初期信用枠も同時に付与されます。

4.相互性：信用枠を利用するには、有効な提供を掲載し続ける必要があります

信頼を得ることで信用限度額（潜在的にマイナスにできる深さ）が決まります。しかし実際にその信用枠を引き出すには、有効な提供を掲載し続ける必要があります。これにより、借りを抱えているメンバーがコミュニティにどのように貢献するつもりであるかを常に示すことになります。

掲載している有効な提供の数によって、利用可能な信用枠が決まります：

有効な提供数利用可能な信用枠
00 — 保有している豆のみ使用可能
1−200豆まで
2−500豆まで
3−1000豆まで
4−1500豆まで
5−2000豆まで （通常の上限）

実際の利用可能額は、獲得した限度額と有効な提供数による利用可能枠の小さい方になります。

例：取引を通じて−600の限度額を獲得している場合、有効な提供を2件掲載していると−500まで利用できます。3件目を掲載すると限度額いっぱいの−600まで利用可能になります（獲得した限度額にすでに達しているため、4件目や5件目の提供は不要です）。

利用の一時停止（フリーズ）：
現在の負債に必要な有効な提供数を下回った場合（例：提供していたものが売れて取引が完了した場合や、一時停止した場合）、信用枠を利用した支払いが一時停止されます。これはペナルティではなく安全策です。何も没収されることはありません。豆の受け取り、販売、閲覧は引き続き可能です。有効な提供数がカバーする範囲に残高が戻れば（別の提供を掲載するか、豆を受け取ることで）、信用枠の停止は自動的に解除されます。

5.提供（出品リスト）

  • 定期的な提供を含め、いくつでも好きなだけ提供を掲載でき、いつでも公開中または一時停止を切り替えることができます。信用枠にカウントされるのは公開中の提供のみです。
  • 受け取る前に与える： 豆を使用するコミュニティでは、他の人から購入したり「求め」を投稿したりする前に、少なくとも1つの提供を掲載する必要があります。グローバルコミュニティのように豆がない場所では、最初の投稿が「求め」であってもかまいません。
  • 残高がプラスですか？希望であればすべて一時停止しても問題ありません — 提供が必要なのは残高をマイナスにする場合のみです。

6.手数料とコミュニティプール

ごくわずかな2種類の手数料があり、どちらもコミュニティコモンズ（コミュニティが投票によって地域プロジェクトのために使う共有プール）に入ります。企業に奪われるものは一切ありません。

a) マーケットプレイス手数料 — 完了した取引に対して1.5%。 マーケットプレイスでの販売が決済されると、売り手は価格から1.5%差し引かれた額を受け取り、その差額がコモンズに送られます。ギフト（メンバー間の直接送付）は無料です — 返金やシステムによる移動も同様に無料です。

b) プラス残高に対する流通手数料 — 月1回、200豆を超える部分にのみ課金。 累進課税のように、各区分の料率はその枠内にある残高の端数にのみ適用されます：

残高区分月間流通手数料率
0 – 200無料 グリーンゾーン
200 – 5001%
500 – 10001.5%
1000 – 20002%
2000+2.5%

これにより、豆をため込むのではなく循環させるよう穏やかに促します。マイナス残高に流通手数料がかかることはありません — コミュニティのためにすでに信用を背負って活動しているからです。+200の無料ゾーンは最初の−200の信用枠と対になっており、システムはゼロを中心として対称に設計されています。

7.ギフト（豆の送付）

  • 実際に保有している豆のみギフトとして送ることができます — ギフトによって残高がマイナスになることはなく、信用枠を使うこともできません。
  • 実際の取引を少なくとも1回完了すると送付可能になります（作成されたばかりのアカウントが即座に豆を転送して雲隠れするのを防ぐためです）。
  • ギフトは受け取り側の信頼度向上にはならず、手数料は無料です（保有している豆のみ送付可能）。

8.取引の決済方法

マーケットプレイスの取引は、取引が完了するまでエスクロー（システムによる安全な預かり保管）で保持され、その後に売り手に送金されます（1.5%の手数料が差し引かれます）。取引がキャンセルされた場合、買い手に全額返金されます。

9.推薦（オプションのスタートダッシュ）

コミュニティから任命された信頼できる推薦者は、新規メンバーが取引実績を積む前に信用枠を使い始められるよう、25豆、50豆、または100豆のスターター下限枠を付与できます。これは通常、推薦者の裁量により、投稿や貢献が魅力的で心動かされると感じられたメンバーに贈られます。推薦は任意です。取引を行うだけで信用枠を開設できるため（§3）、参加にあたって推薦が必須となる人はいません。

10.コミュニティ間の連邦清算

コミュニティが孤立して存在する必要はありません。連邦取引コネクター（ケインズの清算同盟構想に着想を得たもの）を通じて、独立したコミュニティノード同士が、法定通貨や銀行の準備預金を使わずにP2Pで近隣ノードと取引を清算できます。豆が所属コミュニティの外に出ることはありません — ノードのペア同士が労働の貸し借りを記録するブリッジ台帳を保持し、双方がその上限額を設定します。清算は2つのコミュニティ間で行われ、各運営者が明示的にオンにする必要があります。機能はまだ初期段階であり、Webアプリに画面が構築され、テストコミュニティ間で試行されたのみで、本番環境同士での実績はありません。

11.暗号化アイデンティティと鍵の保管

アカウントはお使いの端末上で生成されるEd25519暗号鍵ペアによって保護されています。BeanPoolはニーズに合わせた柔軟な保管方法を提供します：

  • 完全な自己主権： スマートフォンアプリでは、秘密鍵は端末の安全なストレージ（iOS Keychain / Android Keystore）に保管されます。Webアプリではブラウザ自体のストレージに保管されます。鍵が端末から外に出るのは、サインイン復元用の暗号化されたコピーとして、または自分の別の端末にアカウントをコピーするときのみです。12個の単語のシードバックアップはオフラインで大切に保管してください。
  • 復元： 12個の単語（英語）を使えば、任意の端末でアカウントを復元できます。Google、Apple、Facebookのサインインを連携させることも可能です。その場合、そのサインイン用に暗号化された鍵のコピーが保持されます。BeanPoolのキー保管庫（ヴォールト）を使用するスマートフォンアプリは、アイスランドの小さなサーバーに保管します。古いバージョンのスマートフォンアプリはコミュニティのノードに保管し、グローバルコミュニティのWebアプリは私たちが運営するそのサーバーに保管します。コピーを保管している者（保管先の運営者）は誰でもそれを開くことができます。保管庫からの復元には、自身の別の端末で承認しない限り24時間の待機時間が発生します。端末、12個の単語、サインインのすべてを紛失した場合でも、コミュニティの管理者が対面でワンタイムコードを使って新しいスマートフォンにアカウントを移行できます（履歴は保持されます）。そのため、単語は必ず紙に書き留めてください。

12.制限と安全性

  • 多くのコミュニティで下限の上限は−2000です（§1参照）。1日に使える豆の額に上限はありません — 下限額がその境界となります。頻度には制限があります：任意の24時間内で、支払い100回、これまでに支払ったことのない相手30人、マーケットリクエスト100件までです。
  • 特定の1人の相手との信頼獲得には上限が設けられており、結託した相手と取引を繰り返して不正に信望を吊り上げることはできません。
  • お休みモードにすると、留守中に提供を非表示にし、届くリクエストを一時停止できます。
  • メンバーは悪質な利用者を報告・フラグ付けでき、コミュニティの管理者はそれらを排除できます。

13.コミュニティ事業体とガバナンス

コミュニティ事業体（道具の共有ライブラリ、共同養鶏、薪ステーションなど）や期限付きプロジェクトは、共同管理のもとで行われる共有の取り組みです。これらはプログラムによって厳格に適用される明確なルール（コモンズのガバナンスモデル）に基づいて運営されます：

  • 1つの仕組み、2つのライフサイクル（§2.1）： 継続的な事業体は永続して取引を行います。期限付き事業体（プロジェクト）には目標と終了期日があり、完了時にアカウントを清算して残った資金をコモンズに返還します。
  • 獲得信用による下限と運営者のプレッジ（ルール1〜3）： 新しい事業体は実績のない当座貸越なしでスタートします。その信用下限は、運営者が獲得した取引信望からの明示的なプレッジ（裏付け）によって支えられます（単純合算、人為的な倍率はなし）。裏付けをプレッジしても、運営者個人の世帯信用枠が減ったり影響を受けたりすることはありません。以前から存在する事業体は、プレッジ導入前の初期下限枠を維持します。
  • 有限責任（ルール4）： 破綻するのは事業体であり、運営者の世帯ではありません。事業体が債務不履行に陥った場合、その事業体の支出は凍結されますが、運営者個人の信用枠は保護されます。
  • 信用で仕入れ、利益で人を支払う（ルール5）： 事業体は地域の近隣から物資やサービスを購入するために、利用可能な下限まで信用枠を使うことができます。しかし、自身の運営者に支払うために信用枠を使うことは決してできません — 運営者への支払いは残高 − 支払額 ≥ 0の範囲内でのみ行われます。
  • 獲得剰余金を上限とする運営者報酬（ルール6）： 運営者への支払いは、純粋な取引剰余金（売上収入から過去の運営者支払いを引いた額）によって厳格に制限されます。助成金、プレッジ、ギフトを運営者の報酬に変えることは絶対にできません。
  • 運転資金の自動スイープ（ルール7）： 事業体は運転資金の上限を設定できます。富の囲い込みを防ぐため、上限を超えた獲得剰余金はコミュニティコモンズプールに自動的に回収（スイープ）されます。助成金やギフトが回収されることはありません。
  • 2人承認ルール： 運営者は自分自身への支払いや、事業体の求めに対する個人としての入札を自ら承認することはできません — 必ず別の運営者が承認する必要があります。
  • 投票と決定（§3）： 形式張らない質問はマーケットフィードの投票で行います。1人1票で集計され、拘束力はありません。拘束力のあるガバナンス（プール助成金、債務免除、役職変更、メンバーの利用停止・凍結・除名）は、コモンズタブの決定を通じて7日間の投票期間で行われます。十分な数のメンバー（直近30日間に活動のあったメンバーの30%以上、かつ最低3人。除名の場合は25%）が投票し、60%の賛成（除名の場合は66%。利用停止や凍結の解除、復帰の場合は過半数）で可決されます。可決されると自動的に実行されます。プール助成金は獲得した取引信望に基づく二次投票（クアドラティック・ヴォーティング）を採用しており、保有する豆で票を買うことはできません。
  • 用語の統一（§9）： 4つのレベルと4つの明確な言葉：ノード → オーナー / 管理者 · 事業体 → 代表運営者 / 運営者 · グループ → まとめ役（招集者） · 信頼階層 → 世話人。
