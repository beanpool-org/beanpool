Magsimula ng komunidad

Bawat komunidad ay tumatakbo sa sarili nitong node: isang maliit na server na nagtataglay ng mga miyembro, mga post at talaan ng komunidad na iyon. Isang lokal na tao ang nagpapatakbo nito. Kung wala pa sa iyong bayan o lambak, maaaring ikaw iyon.

Ano ang kasama sa pagpapatakbo ng komunidad

Humigit-kumulang kalahating oras, kung kaya mong sumunod sa panuto. Anim na bagay na dapat munang malaman:

  • Ang gastos nito. Libre ang software. Tumatakbo ito sa isang ekstrang kompyuter na nananatiling nakabukas sa bahay (isang Mini PC, NAS, o Raspberry Pi na may 64-bit system), o sa isang maliit na inupahang server sa halagang ilang dolyar kada buwan (mga US$6).
  • Sino ang nagho-host nito. Ikaw, sa sarili mong makina o sa inuupahan mo. Hindi nito kailanman kailangan ang beanpool.org: gumagana ang sarili mong web address.
  • Ang iyong pananagutan. Dumarating sa iyo ang mga report mula sa iyong mga miyembro. Nasa sa iyo ang pag-backup ng folder ng data, gamit ang isang recovery code. Magpanatili ng dalawang may-ari. Panatilihing nakabukas at updated ang server.
  • Kung ano ang hindi mo kailanman makikita. Ang mga direct message ng iyong mga miyembro.
  • Docker muna. Kailangang may naka-install na Docker ang makina bago ang bloke sa ibaba; ang isang bagong inupahang server ay wala nito.
  • Address na mararating ng mga telepono. Nararating lamang ng mga telepono ang isang komunidad sa internet sa pamamagitan ng https. Sa isang inupahang server na may pampublikong IP address at bukas ang port 80 at 443, sapat na ang IP address na iyon: nakakakuha ang iyong server ng sarili nitong certificate para dito, nang walang Cloudflare account, at ganoon din para sa sarili mong domain. Sa bahay, o kung walang bukas na port, ang pag-claim ay nagbibigay sa iyo ng libreng pangalan na nagtatapos sa .beanpool.org, sa pamamagitan ng tunnel na pinapatakbo mismo ng iyong server. Ang payak na http:// address ay gumagana lamang sa isang home network.
🧰

Ang iyong pinapangalagaan

Ikaw at ang mga admin na itatalaga mo ang mga tagapangasiwa ng iyong komunidad: dumarating sa iyo ang mga report. Nakatira ang data ng iyong mga miyembro sa iyong makina, kaya pinapanatili mo itong naka-back up. Mababasa mo ang mga talakayan sa negosyo at mga chat sa event; hindi mo mababasa ang mga direct message. Iniimbitahan mo ang mga unang miyembro, at iniimbitahan nila ang iba pa.

⚙️

Ang app ng mga setting

May kasamang sariling app ng mga setting sa browser ang iyong node. Mula rito pinapangalanan mo ang iyong komunidad, nagtatalaga ng may-ari at mga admin na nag-sign in gamit ang sarili nilang mga key, nagpi-print ng mga imbitasyong QR, nagbabantay sa kalusugan ng disk, pumipili ng pampublikong web address o tunnel, at tumutulong sa miyembrong nawalan ng parehong telepono at 12 salita pabalik sa sarili nilang account sa bagong telepono, gamit ang isang one-time code na kinukumpirma mo nang personal.

🔒

Pribado mula sa unang pag-boot

Ang mga listing, mapa, mensahe at balanse ng komunidad ay para lamang sa mga miyembro nito mula sa sandaling magsimula ang node nito; walang kailangang buksan. Ang isang magbubukas ng address nito nang walang account ay itinuturo sa pandaigdigang komunidad, kung saan makikita nila kung ano ang malapit sa kanila at humiling na sumali.

🌐

Pag-link sa isang kalapit na komunidad

Maaaring magkasundo ang dalawang komunidad na mag-link upang makipagkalakalan ang kanilang mga miyembro sa isa't isa. Hindi kailanman umaalis ang Munggo sa sariling bayan: ang bawat pares ay nagpapanatili ng tuloy-tuloy na talaan ng kung ano ang utang ng isang komunidad sa isa pa, at bawat panig ay nagtatakda ng sarili nitong limitasyon. Naka-off ang pag-link maliban kung buksan ito ng parehong operator, at maaga pa ito: binuo na ito, kasama ang mga screen nito sa web app, at nasubukan pa lamang sa pagitan ng dalawa sa sarili naming mga pansubukang komunidad, hindi kailanman sa pagitan ng mga live na komunidad.

Ang iyong address

Piliin ito bago ka mag-paste, at baguhin ang huling linya upang tumugma. Kung na-paste mo na, pindutin ang Enter sa mga tanong nito, pagkatapos ay patakbuhin muli ang huling linya: naghihintay ang claim code para sa isang telepono. Isang inupahang server na may pampublikong IP address at bukas ang port 80 at 443: idagdag ang --ip at ang IP address nito, tulad ng sa beanpool claim --ip 203.0.113.7. Nakakakuha ang iyong server ng sarili nitong certificate para sa address na iyon mula sa Let's Encrypt, sa port 80, at nararating ito ng mga telepono sa https://203.0.113.7. Isang kompyuter sa bahay, o walang bukas na port: iwanan ito kung ano ito. Hihingi ito ng unang bahagi ng isang libreng pangalan (i-type lamang ang yourtown para sa yourtown.beanpool.org; lalampasan ito ng Enter), na nararating sa pamamagitan ng tunnel na pinapatakbo mismo ng iyong server, at naghihintay ng hanggang tatlong minuto para maging live ito. Sarili mong domain: ituro ang isang A record para dito sa IP address ng server, buksan ang port 80 at 443, at idagdag ang --address https://your.domain. Nananatili ang isang pangalan sa pagpapalit ng server; ang isang numero ay hindi: maaari kang magdagdag ng pangalan sa ibang pagkakataon sa Mga Setting, at ang mga miyembro na gumagamit ng IP address ay patuloy na gagana. Upang pumili sa ibang pagkakataon sa Mga Setting, idagdag ang --no-name. Ang payak na http:// address ay gumagana lamang sa isang home network: tinatanggihan ito ng mga telepono sa internet, at binabalaan ka ng pag-claim. Kung hindi gumagana ang serbisyo ng address ng proyektong BeanPool, gagana pa rin ang pag-claim.

I-install ito

Pagkatapos, sa makinang iyon na may naka-install na Docker, i-paste ang isang blokeng ito. Kinukuha nito ang compose file, ginagawa ang network na ginagamit ng node, pinu-pull ang na-publish na image (Intel/AMD o ARM64), sinisimulan ito, naghihintay hanggang magawa ng server ang one-time claim code nito (hanggang limang minuto, para sa mabagal na unang pagsisimula sa isang Raspberry Pi), at kini-claim ito. Walang kailangang i-configure bago ito magsimula.

The server's log says why: docker compose logs beanpool-node" docker compose exec beanpool-node beanpool claim

Ang huling linya: beanpool claim

  1. Ang code at QR. Nagpapakita ito ng isang one-time claim code at isang QR code. I-scan ang QR code gamit ang camera ng iyong telepono, o buksan ang BeanPool, i-type ang address ng server sa ilalim ng Hanapin ang iyong komunidad at i-tap ang I-claim. Ang teleponong iyon ang magiging may-ari.
  2. Mga Setting. Buksan ang iyong address (o ang sariling address ng server) na sinusundan ng /settings. Pinapangalanan ng setup wizard ang iyong komunidad, hinihiling sa iyo na magdagdag ng pangalawang may-ari, at gumagawa ng tatlong pampundasyong imbitasyon. Itakda ang iyong lugar sa mapa sa ilalim ng Pagkakakilanlan ng Node upang mahanap ka ng mga tao sa malapit.

Kung sinabi ng block na No claim code after 5 minutes, o sinabi ng beanpool claim na This community has no claim code waiting, hindi pa natapos magsimula ang server: ipinapakita ng docker compose logs beanpool-node kung nasaan ito. Kapag sinabi ng log na wala pang may-ari ang komunidad at may claim code na, patakbuhin muli ang huling linya. Ang buong mga hakbang ay nasa unang pag-set up ng manwal ng operator.
